# 给后端组员的接口说明（SQL 编译器 → 执行引擎）

> 前端（SQL 编译器）同学写。后端（执行引擎 + 页式存储）同学接手前，只需要读这一份就够了——**不用读懂 Lexer/Parser 的实现细节**，只要看懂下面三件事：我们产出了什么、它长什么样、你们从哪里接着写。

---

## 0. 先看这张图（三个模块怎么衔接）

```
SQL 文本
   └─ 前端（我们）：SQL 编译器
        → ① Lexer（词法）     → Token 流
        → ② Parser（语法）    → AST
        → ③ Semantic（语义）  → 名字绑定 + 类型检查 + Catalog
        → ④ Planner（计划）   → Logical Plan（算子树）
        → ⑤ Optimizer（优化） → Optimized Plan  ★ 我们的终点
   └─ 后端（你们）：从这里接着写
        → 执行引擎：读 Plan，逐个算子执行
        → 页式存储：提供"表 → 数据页 → 记录"的读写
```

**一句话约定：我们负责把 SQL 翻译成"执行计划"；你们负责把这个"执行计划"真正跑起来。**

---

## 1. 我们交付了什么

1. 一个能编译运行的 Java 工程（`build.bat` 编译、`run.bat` 运行）。
2. 一条流水线 `Main`：输入 SQL，依次打印 `Token → AST → Semantic → Plan → Optimized Plan`。
3. **核心交付：优化后的逻辑执行计划 `Plan` 树**，以及你们执行时要查表结构的 **`Catalog`**。

---

## 2. 你们从哪里接着写

打开 `src/minisql/Main.java`，第 ⑤ 步之后（打印完"优化后"的 Plan）就是分界点。那里的 `Plan after`（类型 `minisql.plan.Plan`）就是你们执行引擎的输入。

你们要新建自己的包（比如 `minisql/executor/`），写一个"执行器"，拿到 `Plan` 后开始执行。**我们这边不再改动 Plan 的结构**，这就是前后端的契约。

---

## 3. 核心接口：逻辑执行计划 Plan

### 3.1 结构

所有 Plan 节点都继承自 `minisql.plan.Plan`，它只有一个字段：

```java
public final Plan child;   // 唯一的子节点；叶子节点为 null
```

计划树是**一条单链**（每节点最多一个子节点），从上到下执行。

### 3.2 五种节点（PPT 第 30 页）

| 节点类 | 字段 | 执行语义（你们要实现的动作） |
|--------|------|------------------------------|
| `SeqScanPlan` | `Table table`；`String purpose` | 顺序读出 `table` 的所有行，作为"行流"向上输出。`purpose == "DELETE"` 表示这是删除扫描。 |
| `FilterPlan` | `Expr predicate`；`Plan child` | 对 `child` 输出的每一行求值 `predicate`，只保留结果为 `true` 的行。 |
| `ProjectPlan` | `List<String> columns`；`Plan child` | 对 `child` 输出的每一行，只保留 `columns` 里列出的列。 |
| `InsertPlan` | `Table table`；`List<String> columns`；`List<Expr> values` | 求值 `values` 得到一条记录，写入 `table`。`columns` 为空表示按表全部列。 |
| `CreateTablePlan` | `String tableName`；`List<ColumnDef> columns` | 在存储里建一张空表（表结构由 `columns` 给出）。 |

> 注：`DELETE` 语句在计划里表达为 `Filter(条件) → SeqScan(表, purpose="DELETE")`，没有单独的 Delete 节点。

### 3.3 执行顺序

计划是自底向上（`child` 先执行，父节点用子节点的结果）：

- `Project → Filter → SeqScan`：先 `SeqScan` 扫出所有行，再 `Filter` 过滤，再 `Project` 选列。
- 一个简单的执行骨架（伪代码，供理解，不替你们实现）：

```java
ResultSet execute(Plan p) {
    if (p instanceof SeqScanPlan)   return 扫描表(p.table);          // 读所有行
    if (p instanceof FilterPlan)    { 子结果 = execute(p.child); return 子结果.filter(p.predicate); }
    if (p instanceof ProjectPlan)   { 子结果 = execute(p.child); return 子结果.project(p.columns); }
    if (p instanceof InsertPlan)    { 存储写入(p.table, 求值(p.values)); return null; }
    if (p instanceof CreateTablePlan){ 存储建表(p.tableName, p.columns); return null; }
}
```

### 3.4 表达式 Expr（执行 Filter / Insert 时要用）

谓词和插入值都是 `minisql.ast.Expr`，有 4 种子类。你们需要一个"表达式求值器"（`Expr + 一行数据 → 一个值`）：

| 子类 | 字段 | 求值方式 |
|------|------|----------|
| `ColumnRef` | `String name` | 取当前行 `name` 列的值 |
| `Literal` | `Object value`；`DataType type` | 直接返回 `value` |
| `BinaryExpr` | `String op`；`Expr left/right` | 先求值左右，再按 `op` 运算 |
| `UnaryExpr` | `String op`；`Expr operand` | 求值 `operand`，再 `NOT` 或取负 |

`op` 可能的取值（求值器要全覆盖）：

- 算术：`+ - * /`
- 比较：`= != < > <= >=`
- 逻辑：`AND OR`
- 一元：`NOT`、`-`（负号）

> 我们前端已经用同一个 Expr 做过**类型检查**和**常量折叠**（参考 `SemanticAnalyzer.typeOf`、`Optimizer.evalBinary`），你们写求值器时类型规则可以照抄那里，保证前后端对"值怎么算"的理解一致。

## 4. Catalog：查表结构的入口

`minisql.catalog.Catalog` 是符号表（PPT 第 25 页说它"还要服务执行引擎与持久化"）。你们执行引擎里要查"某张表有哪些列、每列什么类型"，就通过它：

```java
Catalog catalog = ...;                  // Main 里已经建好一个
Table t = catalog.findTable("student"); // 按表名查（大小写不敏感，返回 null 表示不存在）
t.columns;                              // List<ColumnDef>，每列有 name + type
t.findColumn("age");                    // 按列名查，返回 ColumnDef 或 null
```

`ColumnDef` 有 `name`（String）和 `type`（`DataType`，取值 `INT/FLOAT/VARCHAR/BOOL`）。

## 5. 一个完整例子（demo.sql 的 Plan 怎么执行）

输入（`tests/demo.sql` 里的一条）：

```sql
SELECT name FROM student WHERE age > 18;
```

前端产出的 Plan（优化后）：

```
Project[name]
└─ Filter[age > 18]
   └─ SeqScan[student]
```

执行语义：

1. `SeqScan[student]`：从存储读出 `student` 表的所有行（假设 3 行）。
2. `Filter[age > 18]`：对每行求值 `age > 18`，只留下 `age` 大于 18 的行。
3. `Project[name]`：每行只保留 `name` 列。

最终结果就是"年龄大于 18 的学生的姓名列表"。

## 6. 你们要做的（建议分工）

- **页式存储组员**：定义"页/记录"的底层表示，提供 `建表 / 写入记录 / 顺序读表` 的接口。
- **执行引擎组员**：写表达式求值器 + 执行循环（第 3.3 节的骨架），调用存储接口，把 Plan 跑出结果。

两边先对好一个"一行数据（Row）"怎么表示（比如 `Map<String,Object>` 或自定义类），执行引擎和存储就靠它衔接。

## 7. 常见疑问

**Q：前端已经做了类型检查，后端执行时还要不要再查一次？**
不用。语义分析（第 ③ 步）已经保证能跑到 Plan 的 SQL 都是"表/列存在、类型正确"的。后端只负责执行，遇到意外再兜底报错即可。

**Q：`SELECT *` 在 Plan 里怎么表示？**
`ProjectPlan.columns` 会被展开成该表的**全部列名**（不是存一个 `*`）。所以后端看到 `Project` 的 `columns` 就是最终要返回的确切列。

**Q：优化后的 Plan 和优化前结构不一样，执行时用哪个？**
用**优化后**的（`Main` 第 ⑤ 步里 `after` 那个）。优化只是让计划更高效，语义完全等价。

## 附录 A：Python 组员怎么读 JSON（跨语言衔接）

> 前端是 Java，你们后端用 Python——**没关系**。前端跑完后会把优化后的 Plan 输出成 JSON（控制台第 ⑥ 步会打印，同时写成 `plan.json` 文件）。你们用 `json.loads` 读进来就是一棵嵌套的 dict 树，照着写执行引擎即可，**完全不用碰 Java 代码**。

### A.1 接口就是这些字段名

JSON 里每个节点都有一个 `"kind"` 字段标明类型，其余字段和第 3 节的 Plan 节点一一对应：

| kind | 字段 | 含义 |
|------|------|------|
| `SeqScan` | `table`、`purpose` | 扫表；`purpose` 是 `SELECT` 或 `DELETE` |
| `Filter` | `predicate`、`child` | 过滤；`predicate` 是 WHERE 表达式 |
| `Project` | `columns`、`child` | 投影；`columns` 是要返回的列名 |
| `Insert` | `table`、`columns`、`values` | 插入；`values` 是表达式数组 |
| `CreateTable` | `table`、`columns` | 建表；`columns` 是 `[{"name":..,"type":..}]` |

表达式（`predicate` / `values` 里的对象）的 kind：`ColumnRef`（字段 `name`）、`Literal`（`type` + `value`）、`BinaryExpr`（`op` + `left` + `right`）、`UnaryExpr`（`op` + `operand`）。

`Literal` 的 `value` 被 `json.loads` 自动还原成 Python 类型：`INT→int`、`FLOAT→float`、`VARCHAR→str`、`BOOL→bool`。

### A.2 Python 执行引擎骨架

```python
import json

def execute(plan: dict):
    """自底向上执行一棵 Plan（dict）。"""
    kind = plan["kind"]
    if kind == "SeqScan":
        return scan_table(plan["table"])                 # 从你们的存储层读所有行
    if kind == "Filter":
        rows = execute(plan["child"])
        return [r for r in rows if eval_expr(plan["predicate"], r)]
    if kind == "Project":
        rows = execute(plan["child"])
        cols = plan["columns"]
        return [{c: r[c] for c in cols} for r in rows]
    if kind == "Insert":
        vals = [eval_expr(v, {}) for v in plan["values"]]
        write_row(plan["table"], plan["columns"], vals)  # 写入你们的存储层
        return None
    if kind == "CreateTable":
        create_table(plan["table"], plan["columns"])     # 在存储层建空表
        return None
```

### A.3 表达式求值

```python
def eval_expr(expr: dict, row: dict):
    """对一行数据求一个表达式的值。"""
    k = expr["kind"]
    if k == "ColumnRef":
        return row[expr["name"]]
    if k == "Literal":
        return expr["value"]
    if k == "UnaryExpr":
        v = eval_expr(expr["operand"], row)
        return (not v) if expr["op"] == "NOT" else -v    # op 是 NOT 或 -
    if k == "BinaryExpr":
        l, r = eval_expr(expr["left"], row), eval_expr(expr["right"], row)
        op = expr["op"]
        if op == "+":   return l + r
        if op == "-":   return l - r
        if op == "*":   return l * r
        if op == "/":   return l / r
        if op == "=":   return l == r
        if op == "!=":  return l != r
        if op == "<":   return l < r
        if op == ">":   return l > r
        if op == "<=":  return l <= r
        if op == ">=":  return l >= r
        if op == "AND": return l and r
        if op == "OR":  return l or r
```

> 类型规则前端已经查过一遍（`WHERE` 一定是 BOOL、`INT + VARCHAR` 会报错），你们求值时遇到意外再兜底即可。

### A.4 一个完整例子

`SELECT name FROM student WHERE age > 18;` 前端产出的 JSON（`plan.json` 里的一条）：

```json
{"kind":"Project","columns":["name"],"child":{"kind":"Filter","predicate":{"kind":"BinaryExpr","op":">","left":{"kind":"ColumnRef","name":"age"},"right":{"kind":"Literal","type":"INT","value":18}},"child":{"kind":"SeqScan","table":"student","purpose":"SELECT"}}}
```

Python 侧 `execute(json.loads(上面那段))`：先 `SeqScan` 读 student 所有行 → `Filter` 保留 `age > 18` 的行 → `Project` 只留 name 列。

**拿 JSON 的方式**：前端运行 `run.bat tests\demo.sql` 后，`plan.json` 会出现在项目根目录——里面是一个 JSON 数组，按语句顺序排列优化后的 Plan，你们直接 `json.load(open('plan.json'))` 遍历执行即可。
