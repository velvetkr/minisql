# 页式存储系统 接口说明（Java 版）

本模块是数据库系统的**底层存储层**（对应操作系统部分），提供以「页」为粒度的分配、释放、读写与缓存管理。上层存储引擎通过本模块访问磁盘数据。

- 语言：Java 21
- 构建：Maven
- 包名：`storage`

## 项目结构

```
storage/
├── pom.xml
├── 接口说明.md
└── src/
    ├── main/java/storage/
    │   ├── Constants.java              # 常量：页大小 4KB、超块页号、魔数等
    │   ├── StorageException.java       # 异常基类（非受检）
    │   ├── PageNotFoundException.java
    │   ├── PageCorruptedException.java
    │   ├── FileManager.java            # 底层文件 I/O（页号 → 文件偏移）
    │   ├── PageManager.java            # 页分配/释放 + 空闲链表（页 0 超块）
    │   ├── BufferPool.java             # 缓冲池：缓存/脏页/统计，顺序委托给策略
    │   ├── EvictionPolicy.java         # 替换策略接口
    │   ├── LruPolicy.java / FifoPolicy.java / ClockPolicy.java
    │   ├── Demo.java                   # 演示
    │   └── Benchmark.java              # 替换策略对比实验
    └── test/java/storage/
        └── StorageTest.java            # 17 个单元测试
```

## 快速上手

```java
import storage.*;

FileManager fm = new FileManager("data.db");      // 打开/创建数据文件
PageManager pm = new PageManager(fm);             // 页管理（磁盘层）
BufferPool  bp = new BufferPool(pm, 10, "LRU");   // 缓存层，统一入口；策略可选 "LRU"/"FIFO"/"CLOCK"
```

数据库引擎**只需要跟 `bp`（BufferPool）打交道**。

## 核心接口

| 方法 | 说明 | 返回 |
|------|------|------|
| `bp.allocatePage()` | 分配一个空页（优先复用空闲页，否则追加新页） | `int` 页号 |
| `bp.freePage(int pageId)` | 释放页，回到空闲链表 | `void` |
| `bp.getPage(int pageId)` | 读页；命中缓存直接返回，未命中从磁盘加载 | `byte[]`（副本，可安全修改） |
| `bp.writePage(int pageId, byte[] data)` | 写页，`data` 必须正好 4096 字节，自动标脏 | `void` |
| `bp.flushPage(int pageId)` | 若该页为脏，写回磁盘并清除脏标记 | `void` |
| `bp.flushAll()` | 把所有脏页写回磁盘 | `void` |
| `bp.close()` | 等价于 `flushAll()`，退出前调用 | `void` |
| `bp.getStats()` | 命中率、淘汰次数等统计（见下） | `Stats` |
| `bp.getEvictionLog()` | 替换日志（字符串列表） | `List<String>` |

### `Stats` 记录（`bp.getStats()` 返回值）

```java
public record Stats(String policy, int capacity, int size, int hits, int misses,
                    double hitRate, int evictions, int dirtyEvictions) {}
```

字段含义：`policy` 策略、`capacity` 容量、`size` 当前缓存页数、`hits` 命中数、`misses` 未命中数、`hitRate` 命中率、`evictions` 淘汰次数、`dirtyEvictions` 脏页淘汰次数。

## 替换策略（BufferPool 第三个参数）

| 策略名 | 说明 |
|--------|------|
| `"LRU"` | 最近最少使用（默认推荐） |
| `"FIFO"` | 先进先出 |
| `"CLOCK"` | 时钟 / 第二次机会 |

三种策略通过 `EvictionPolicy` 接口实现，加新算法 = 新增一个实现类，**无需改动 `BufferPool`**。

## 关键约定（务必遵守）

1. **页 0 被占用**：页 0 是超块（存魔数、空闲链表头），**数据页从 1 开始**，不要读写或释放页 0。

2. **`getPage` 返回的是副本**：返回的 `byte[]` 是缓存内容的克隆，修改它**不会**影响缓存。要真正改页，请修改副本后调用 `writePage(pageId, 修改后的副本)`。

3. **职责边界**：本模块只提供「页」粒度。**表 → 页集合的映射、行 ↔ 页的序列化由存储引擎负责**，它拿到页字节后自行解释。

4. **持久化**：所有写操作先留在缓存，`close()` / `flushAll()` 才真正落盘。**程序退出前必须调用**，否则脏页丢失。

5. **异常是非受检的**：`PageNotFoundException`、`PageCorruptedException` 都继承 `RuntimeException`，调用方不必写 `throws`，但可自行 `try/catch` 处理越界、文件损坏等情况。

## 完整最小示例

```java
import storage.*;

public class Example {
    public static void main(String[] args) {
        BufferPool bp = new BufferPool(new PageManager(new FileManager("data.db")), 10, "LRU");

        int pid = bp.allocatePage();                       // 拿到一个空页
        byte[] data = new byte[Constants.PAGE_SIZE];       // 构造 4096 字节
        bp.writePage(pid, data);                           // 写入
        byte[] read = bp.getPage(pid);                     // 读回（命中缓存）
        bp.close();                                        // 落盘，退出前必须调用
    }
}
```
